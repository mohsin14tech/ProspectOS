# ProspectOS screen audit

## Email browser review — 2026-11-15

Authenticated review covered mailbox setup and inbox at 390px and 1280px, light/dark appearance, Gmail preset, empty states and keyboard focus. Form controls measured 48px tall and no document-width overflow was observed. A sticky Save overlap with a focused username field was found and fixed by returning the action to normal flow while a field is focused; repeat measurement confirmed the overlap was gone. Dark-mode email links use a brighter color and body copy uses 16px. Gmail preset correctly fills `imap.gmail.com`, `smtp.gmail.com` and port 465. Original appearance was restored and temporary viewport override removed.

The owner-workspace Ollama test passed visibly and the database confirms tested/active. Email connections remain unconfigured. Populated mailbox and SMTP approval history were checked through functional tests, not a real mailbox browser session. Full screen-reader, 200% zoom, all-device and PWA-install verification are still open. Screenshots live under ignored `var/verification/`; do not publish private mailbox screenshots.

This audit records the current screen job, primary action, decisions, states, responsive behavior, and known gaps. It reflects the shipped early-access scope; it does not certify WCAG conformance.

## Theme and interaction update

- Authenticated shell uses a platform system font stack, neutral surfaces, restrained accent colors, concise hierarchy and native-feeling controls. Apple system fonts are used only when the browser/OS provides them; SF files are not bundled. See [Apple typography guidance](https://developer.apple.com/documentation/technologyoverviews/fonts) and [Apple color guidance](https://developer.apple.com/design/human-interface-guidelines/color).
- The Appearance popover lets a person select system/light/dark appearance, one of four accents, comfortable/compact spacing, and expanded/compact desktop navigation; Reset restores defaults. Preferences persist in the browser's local storage and do not sync to another device or user account. The compact navigation does not hide the mobile tab bar.
- Dark tokens cover shared surfaces, navigation, forms, reports, integration states, inbox rows, feedback states and the provider setup. Appearance controls respond to keyboard, Escape, pointer and focus; reduced-motion preferences remain respected.
- Browser review should include the signed-out login screen at desktop and 390px. Authenticated screens require an existing test/owner account; do not use a real password in automation or create/modify owner data solely for screenshots.
- Focus visibility, labels, semantic landmarks and visible status/error roles are present in the templates, but keyboard-only, screen-reader, contrast-ratio and 200% zoom verification still require a complete accessibility pass. Do not claim WCAG 2.2 AA conformance until measured and tested.
- AI provider setup has a dedicated layout and stylesheet: route-choice progress, a source-to-destination preview, contextual credentials and local-model guidance, a separate connection-verification panel, and field-linked errors. Its responsive breakpoints are 820px and 560px. The page links its CSS through Asset Mapper directly; no JS CSS import is required.
- The product-wide redesign is CSS-layered over existing screen-specific structure and behavior. It is an Apple-inspired web experience, not a pixel reproduction of a native Apple app. The `system-ui.css` layer is loaded after page styles to keep shared shell and preferences consistent.
