# Security

## Current email security update — 2026-11-15

This section supersedes older draft-only Gmail/no-send statements below. Gmail requests readonly + compose scopes and only invokes reads/drafts. IMAP/SMTP credentials are encrypted, with a new password required before reusing a connection at changed hosts or a changed username. TLS is mandatory, DNS results must all be public and the socket connects to a validated IP while verifying the original hostname. SMTP must authenticate; anonymous relay acceptance cannot pass the login test.

SMTP is limited to labelled tests with admin membership, tested connection, global/workspace pause, immutable payload and original-connection-bound 15-minute approval, suppression, five attempts/hour and a committed one-attempt claim. Uncertain outcomes do not retry. Email responses enforce private/no-store, no-referrer, nosniff and frame denial. Mail is escaped plain text; remote images/HTML/attachments are not displayed. Cached mail is workspace-shared database content, not separately encrypted; only credentials have field-level encryption. Protect database backups and use admin cache clearing/disconnection as appropriate. Full boundaries: [MAIL.md](MAIL.md).

Docker's build context now explicitly excludes `.env`, private env overrides, local PHPUnit config and test cache. The audit found `.env` was previously omitted from exclusions; no image was published, and the corrected build was verified with an empty image `.env`. Keep screenshots, cache and logs in ignored `var/` and scan final publication files/history.

## Current posture

- No production secrets or provider credentials are present in the repository.
- Seeded demo values remain fictional. A live SearXNG search can store public web-result titles, URLs and snippets as unverified candidates in the authenticated user's workspace.
- The research form applies CSRF validation and a 12–500 character objective bound. A search objective is forwarded by the local SearXNG service to upstream engines; the UI warns users not to submit personal/confidential content.
- Synthetic research remains clearly marked. Optional page inspections use `PublicUrlPolicy` to allow HTTP(S) standard ports only, reject credentials and local/metadata hosts, reject any DNS result outside PHP's global-address range, and pin requests to an approved IP. Automatic redirects are disabled; up to three redirect hops are manually resolved and checked again. HTTP requests are bounded by HTML content type, 1 MB, 5-second idle timeout and 12-second total duration. No scripts or subresources are executed/fetched.
- Website inspection fetches and parses `/robots.txt` before page content using the `ProspectOS-Research` product token, and follows up to five safely revalidated robots redirects. A matching disallow rule blocks the page. A 404 or ordinary 4xx response is treated as unavailable under RFC 9309; 401, 403, 429, 5xx, malformed/oversized responses, timeouts and network errors fail closed. Robots rules are a crawler request signal, not authorization or proof that the site's terms permit access; the operator must check and follow the site's applicable terms. Page content is untrusted.
- Shared host controls use PostgreSQL advisory locks for one active inspection per hostname and an indexed PostgreSQL gate row for a two-second minimum interval between inspections. Host gate records older than 30 days are cleaned during later inspections. A single inspection has a 20-second total deadline, one-megabyte page cap and 512,000-byte robots cap. These controls coordinate only app/worker processes sharing this PostgreSQL database; they are local application limits, not a production crawling service guarantee.
- SearXNG web search is available in local Compose and is not exposed on a host port. Search terms leave the local machine through configured upstream engines. AI defaults to disabled; the UI discloses the selected provider and the prospect name, objective, source URLs, bounded evidence and similar team decision examples sent to it. Evidence is untrusted prompt data, output citation IDs are validated, and summaries record provider/model. Summary and provider-test actions share a limit of 10 per signed-in user per hour. Workspace AI keys are encrypted with purpose-separated authenticated encryption and a key derived from `APP_SECRET`; provider setup is owner/admin-only, provider hosts are fixed, and Ollama endpoints are restricted to localhost, Docker host or service names on port 11434. Each workspace can retain multiple provider connections with one active route; editing a connection clears only its test state. A real Ollama inference now passes through the Symfony AI provider service in a temporary test workspace. Gemini remains untested.
- First-owner setup requires a token supplied through the private app environment and becomes unavailable after the first user is created. A PostgreSQL advisory transaction lock prevents concurrent first-owner creation. Registration remains closed. Email verification and password reset are not implemented. Google OIDC uses the official Google PHP client, requests only `openid email`, validates signature/audience/issuer/expiry via the client and `email_verified`/nonce in app code, and identifies accounts by unique `sub`. Only existing linked members may sign in; email equality never merges accounts. Linking requires authentication, CSRF and password reauthentication. Google credentials are absent and real sign-in is unverified.
- Gmail OAuth uses a session-bound state value and one workspace connection. Refresh tokens are encrypted with a key derived from `APP_SECRET`; keys and tokens are not logged or displayed. The `gmail.compose` grant is restricted and permits draft management plus sending, but ProspectOS only invokes `users.drafts.create` and has no send method. The actual connection/API operation is not live-tested. The app requires a finalized lead, CSRF-protected draft form, recipient-basis attestation and a workspace suppression check before creating a draft. Suppressions are manually maintained; no unsubscribe event ingestion exists. Users must review any Gmail draft themselves before sending it from Gmail.
- Login uses Symfony password hashing, CSRF protection, and a five-attempt-per-15-minute login limiter. Session fixation protection uses Symfony's default `migrate` strategy. Session cookies are HttpOnly, SameSite=Lax and Secure when the request is HTTPS.
- Dashboard and research routes require an authenticated user and resolve the workspace through `WorkspaceMembership`; missing membership is denied. Team management and workspace switching are not implemented yet.
- The synthetic demo summary is available only over local STDIO. `/mcp/workspace` exposes read-only summary and prospect-report tools and requires `ROLE_USER`; every query resolves the authenticated user's membership, and prospect IDs are filtered against that workspace. The MCP SDK's HTTP DNS-rebinding protection remains enabled. HTTP MCP currently uses the app's session cookie; OAuth bearer authentication and external-client onboarding are not configured. Do not expose this route publicly until those are implemented and reviewed.
- The local app binds to loopback and PostgreSQL has no host port mapping. Default database credentials and the Compose app secret are for development only and must not be exposed publicly.

## Required before live use

- Add member invitation and role-checked team management, workspace switching, and password reset after an email provider is configured. Review authorization for every new route, service and MCP capability.
- Store user-provider tokens encrypted at rest; never log or re-display their values.
- Treat `APP_SECRET` rotation as credential-key rotation: encrypted Gmail and AI credentials must be reconnected/re-entered after a secret change. The current app has no key rewrapping or recovery mechanism.
- Before adding any send operation, add auditable consent/suppression checks, rate limits, a global outbound pause and human approval tied to an immutable action payload. The current app creates Gmail drafts only; sending remains outside ProspectOS.
- Validate webhook signatures, idempotency and replay windows.
- Prevent SSRF by allowing only HTTP(S), rejecting credentials and unsafe ports, resolving and blocking private/loopback/link-local/metadata destinations, and rechecking redirects and resolved IPs.
- Review SearXNG upstream engine terms and fair-use requirements before public or sustained production use; local search availability is not a production SLA.
- Treat web pages and remote MCP output as untrusted prompt input.
- Keep MCP HTTP restricted to local authenticated use until OAuth bearer authentication, external-client onboarding and deployment host/origin settings have been implemented and reviewed.
- Cache only non-sensitive static PWA assets; do not store private conversations or secrets offline.
