## 2026-11-14 — Robots policy and shared website host controls

- Added `RobotsTxtFetcher` and `RobotsTxtPolicy`; direct website inspection now requests same-origin `/robots.txt` with the `ProspectOS-Research` product token before the requested page. It selects specific matching agent groups before wildcard groups, applies longest matching path rules, honors `*` and terminal `$`, and lets `Allow` win equal-specificity ties. It follows up to five redirects and runs each destination through `PublicUrlPolicy` (including DNS/IP pinning). It rejects non-plain-text or invalid UTF-8, files over 512,000 bytes, 401/403/429, 5xx, network/timeouts, invalid/unsafe redirects and other failure paths. Ordinary 4xx such as 404 are treated as unavailable under RFC 9309. A robot disallow stops the content request.
- Added a 20-second total budget across robots checks, redirects and page fetch, in addition to the existing 1 MB page cap. The research form tells users to check that site terms permit automated requests. Documentation clarifies robots rules are a crawl signal and do not grant legal permission; terms remain the operator's responsibility, and this feature does not fetch/interpret arbitrary terms pages.
- Added a PostgreSQL `website_host_access_gate` migration/entity and `PostgreSqlHostAccessGateInterface` implementation. It takes a dedicated DBAL session (separate from Messenger's application transaction) for session advisory locks, limits to one active inspection per hostname across app/worker processes, and writes shared DB pacing state requiring two seconds between starts. Old host state (>30 days) is cleaned on later gate use. A failure to acquire or pass the interval fails fast with a safe retry-later error. Migration `Version20261114103000` is applied in dev and test; both database schemas validate.
